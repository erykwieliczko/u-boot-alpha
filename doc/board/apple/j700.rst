MacBook Neo (J700): inherited console bring-up
============================================

This is a **console bring-up** T8140/A18 Pro configuration, not a full
platform port. It retains iBoot's scanout through m1n1 and exposes U-Boot's
video, built-in keyboard and physical UART consoles. Storage, USB, Linux boot, cold
UART initialization and system reset are not provided by this configuration.

Build and package
-----------------

Build m1n1 stage2 with its J700 display-only handoff support, using
``RELEASE=1 CHAINLOADING=0``. Then, from the U-Boot tree::

    make O=build-j700 CROSS_COMPILE=aarch64-linux-gnu- apple_j700_defconfig
    make O=build-j700 CROSS_COMPILE=aarch64-linux-gnu- -j8
    python3 tools/apple_m1n1_payload.py \
        --stage2 ../m1n1-alpha/build/m1n1.bin \
        --dtb build-j700/arch/arm/dts/t8140-j700.dtb \
        --uboot build-j700/u-boot-nodtb.bin \
        --output boot-j700.bin

The package is raw m1n1 stage2, the J700 FDT, a gzip-compressed ARM64 U-Boot
Image, and a payload terminator. m1n1's normal payload parser selects
``apple,j700``, decompresses U-Boot into a 2 MiB-aligned allocation, prepares
the FDT and performs its normal cache/MMU teardown before entry with the FDT
in x0. This is not an alternative proxy-only boot ABI.

RAM-chainload this package using the usual target-verified m1n1 loader. The
configuration does not require replacing installed stage1 or writing storage.
A loader which waits for another m1n1 proxy will time out after this image
successfully enters U-Boot; stop sending proxy requests after the handoff and
use the ordinary text console instead.

Runtime contract
----------------

The supplied FDT identifies ``apple,j700`` and ``apple,t8140`` and opts into
``/chosen/asahi,display-only``. m1n1 recognizes that option only on J700/T8140.
It supplies usable memory and framebuffer geometry from the live boot and
retains its normal firmware, FDT, chainload and CTRR reservations. No physical
RAM or framebuffer address is hardcoded into the payload packager. The input
FDT's disabled framebuffer and address-less memory node must be fixed up by
m1n1; the build-time DTB is not directly bootable.

U-Boot maps the 0x300000000..0x3ffffffff console MMIO aperture as device memory,
usable DRAM as normal memory, and the inherited framebuffer separately as
normal non-cacheable memory. Other T8140 apertures are intentionally absent.
``simple_video`` uses the live padded stride, not width times pixel size.

The environment is RAM-only. There is no automatic bootflow, storage scan,
or USB initialization. ``ARCH_APPLE`` currently forces USB
core/command support; the XHCI core is selected to satisfy that build dependency,
but no host-controller frontend or USB node is enabled. Existing Apple
configurations retain their original behavior.

The boot command prints ``NEO U-BOOT - KEYBOARD TEST`` after console initialization,
then leaves the prompt on screen. The upstream EFI hello application is built
in for a storage-free EFI text-output smoke test::

    bootefi hello ${fdtcontroladdr}

This is not an interactive UEFI shell. Commands can be entered through the
built-in keyboard or physical UART. Booting a full OS requires a
complete device tree and additional handoff support, not simply removing the
display-only flag from this sparse tree.

Built-in keyboard
-----------------

The keyboard uses MTP DockChannel, not USB or the debug DockChannel UART.
The ASC control register and polling mailbox work through the existing RTKit
helper and mailbox drivers. At the tested iBoot/m1n1 boundary, MTP is stopped
with firmware preloaded in SRAM. U-Boot starts a fresh RTKit session; the
T8132 retained-session workaround is deliberately not enabled on T8140.

The live ADT identifies mapper-mtp stream 0. The T8140 DART path configures
bypass only for explicitly connected streams with no valid firmware TTBR;
it does not clear other streams or their tables. Hardware reads back the DART
bypass bit, but not the requested DAPF bypass bit. m1n1 separately programs the
ADT-described MTP DAPF and reserves the firmware segments. No unverified SRAM
tail is stolen for shared buffers: the helper uses U-Boot-owned DRAM with the
configured bypass path. This console milestone does not validate OS ownership
transfer or Linux keyboard support.

Captured firmware discovery announces ``multi-touch`` (1), ``keyboard`` (3),
and ``mtp`` (2), with no ``stm``. The 189-byte keyboard HID descriptor describes
the existing report-ID-1 modifier, six-key and Fn layout. Interface IDs remain
dynamically discovered. Captured press/release frames carry a 20-byte body
with a 10-byte HID payload and two alignment bytes. Unlike J713's 12-byte
subheader length, J700 excludes that padding from the reported length. The
parser accepts these two exact lengths while retaining frame-size, checksum
and interface filtering. Captured J700 frames are regression fixtures.
Only ``apple,t8140-dockchannel-hid`` permits missing
STM; the generic driver still requires it. If STM is present, its normal
initialization is retained. The separate ``mtp`` interface is never treated
as STM. Touchpad firmware/reset support is not enabled.

The standard keyboard uclass probes ``mtpkbd`` during stdio initialization,
before board_late_init. ``stdin=serial,mtpkbd`` feeds the normal U-Boot/EFI
input path. At the on-screen prompt, type::

    echo NEO-KEYBOARD-OK

Also check Shift, Backspace, Enter, arrow-key history, Ctrl-C and key release.
Seeing ``MTP keyboard ready`` alone is not a physical-input acceptance test.

Inherited UART mode
-------------------

``apple,t8140-uart`` is an initial inherited-console implementation. It requires
32-bit register accesses, an already configured UART, and ``current-speed``
matching the requested console baud rate. J700 uses 115200 baud for this path.
Probe and setbrg preserve the inherited control, FIFO, clock and divisor state;
unsupported baud changes return an error. RX-ready, TX-ready and TX-empty are
polled through UTRSTAT, using the predicates already exercised by m1n1.

Hardware experiments found that FIFO-full TX polling corrupted output, and
writing the old generic UCON value broke the previously readable stream.
Preserving UCON and using TX-ready pacing reached U-Boot's real unsupported-SoC
panic before the T8140 map was added. This is not proof of the meaning of each
T8140 UCON/FIFO field. Cold initialization needs separate documentation and
validation. The inherited mode is selected only by the new compatible; the
existing Apple and Samsung compatibles use their original code paths.

Validation
----------

Host-side packaging tests::

    python3 -m unittest discover -s tools -p apple_m1n1_payload_test.py

The sandbox ``ut lib`` tests ``apple_mtp_frame``, ``apple_mtp_init_name``,
``apple_mtp_neo_interfaces`` and ``apple_mtp_neo_keys`` cover framing, captured
interface names and unpadded J700 reports alongside the padded M4 format.

Hardware checks include the visible marker, ``coninfo`` and ``dm tree`` showing
active ``simple_video``/``vidconsole``, and ``bdinfo`` confirming high-address
RAM and a separate framebuffer. Keep watchdog state deliberate: this human
console test inherits the disabled watchdogs from m1n1; disabling a U-Boot
configuration symbol alone would not disarm a running hardware watchdog.

On 2026-09-06, J700 completed two RAM-loaded boots through the normal m1n1
payload path. The user confirmed readable on-screen output. Runtime checks
reported 7.6 GiB usable RAM and a 2408 x 1506 x 32 framebuffer with 9664-byte
stride. Bidirectional physical UART worked, the EFI hello application printed
through EFI text output and returned to the prompt, and a subsequent ten-second
idle command completed. The M1 and J713 U-Boot configurations also built; this
does not substitute for hardware regression tests on those machines.

Later the same day, the keyboard-enabled RAM boot completed fresh RTKit
startup and discovered all three interfaces. A first input test exposed the
10-versus-12-byte length distinction above; captured frames had valid checksums
and real press/release transitions. After correcting that check, passive UART
capture showed built-in keyboard typing and Enter reaching U-Boot's command
parser, and the user confirmed that the keyboard worked. ``coninfo`` reported
``mtpkbd`` in stdin; DART error registers were clear and all other stream TCRs
were unchanged. Both m1n1 build modes, J700/M1/J713 U-Boot builds, the four MTP
sandbox tests and payload-builder tests passed. EFI navigation, OS handoff and
touchpad input still require their own validation.

The EFI demo may report that variables cannot be persisted without a system
partition. That is expected for this storage-free test and did not prevent
the application from running. No persistent boot installation was performed.
